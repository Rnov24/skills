Intake notes. Shallow clone at `.work/gluttony/anti-slop`. This repo ships
real code, and all of it was read before any verdict: the npm installer
(`cli/`, ~680 lines: copies skill folders, writes pointer blocks into
agent entry files and a settings JSON — its own product's install
behaviour, no credential access, no network calls), repo-maintenance
scripts (`scripts/check-repo.mjs`, `skill-index.mjs`), the Claude plugin's
contrast-MCP launcher (spawns the Python server), and the two Python files
in antislop-human (a stdlib-only contrast CLI reading local files, and a
stdio JSON-RPC wrapper). Nothing reaches for credentials or sends data
anywhere. Absorption executed none of it; the one script taken was adapted
from source and then run only as the suite's own validation.

Repo shape: a core rulebook duplicated verbatim in two places
(`skills/antislop/SKILL.md`, 724 lines, and root `antislop.md`, 719) —
Craftsmanship standards C-1..C-5, a Part 1 pattern catalogue, rules
R-01..R-38 grouped as Hard Gate / Purpose-Gate / Quality Locks, a Part 3
"Liveliness Toolkit", a Delivery Gate, plus a Two Usage Modes preference
system and a First-Run Install Wizard — and five satellite skills that
reference the core's rule numbers and never renumber them. Distribution
machinery for seven agent hosts (plugin manifests, an npm installer,
skills.sh) makes up most of the remaining tree.

The head-on fact of this audit: the suite already absorbed a design
anti-slop system once (hallmark, A-002), and its taste-core.md is a
checkable anti-slop rulebook holding exactly the seat this core was built
for. The audit question was therefore not quality but residue — what, rule
by rule, the suite lacks. The answer was six mechanisms, all in the
satellites and seams, and they are the whole landing.
