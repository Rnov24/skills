# Macrostructures — the page-shape library

Macrostructure-first composition means the page shape is picked as one
named decision before any section is designed. A macrostructure bundles
heading placement, body composition, divider language, button voice, image
treatment, and reveal pattern into a single fingerprint. Picking one named
shape is faster and far more varied than choosing six independent axes
from scratch, and because the shape has a name, the pick can be recorded,
reviewed, and rotated.

Load discipline mirrors the rest of the shelf: read this index, pick one
name, then read only that one file. Never load the whole library. On
marketing and landing surfaces the shape decision comes from here; app
screens inside a product follow the product's own flows first, and reach
for the Workbench or Component Playground shapes when a screen is really a
surface for doing or demonstrating work.

|---|---|---|

| 04 | Stat-Led | A real metric is the narrative (never with invented numbers) |

| 06 | Conversational FAQ | Honest questions and short answers can carry the whole argument |

## The diversification rule

No two consecutive design outputs in the same project share a
macrostructure, and consecutive outputs differ on at least one direction
axis (paper band, display style, accent hue). The exception is a redesign
under a locked DESIGN.md, where consistency wins and this rule inverts;
see the design skill. Specimen (10) is never a default: reach for it only
when the brief explicitly calls for editorial or specimen energy. When a
brief is vague, pick from shapes 01–09 before reaching further down the
list; they cover most briefs without falling through to the editorial
default. Within a page, no two sections repeat the same component
archetype either; that rule lives in the components index.
